Live Webview

Targeted reload for VS Code webviews.

Clear. Recognisable. Useful.

A window with its live preview stepping forward. The larger frame keeps the compact, overlapping layout; a heading and shorter text line repeat in the front pane to connect an edit with its result. Personality stays secondary.

Visual direction: GitButler's graphic confidence and Things' rounded forms. Preferred layout: the original overlapping window and front pane. Joel approved this layout. The canonical SVG and generated PNGs are available in the brand assets.

An edit and its preview

Both screens contain a small page layout: a heading and a shorter text line. The front pane shows the same layout at a smaller scale. These are content rows, not an abstract symbol. This is visual correspondence, not flipped text or a promise to replay application actions.

The same content, previewed

Keep the larger window and smaller front pane from the first layout. Both screen interiors use a 3:2 rectangle, a 20% left gutter, and the same line widths and vertical spacing. The rear content stays visible above the overlap. A dark separator keeps the light pane distinct from the mint frame.

At 32px and above, preserve the two content rows. The 16px study uses only the overlapping silhouette because the detail needs more room. That micro variant relies on recognition from the larger mark and remains a candidate, not a proven final export.

Text contrast: warm white on charcoal 14.04:1; charcoal on mint 9.39:1. Warm white on mint is 1.49:1, so a dark separator sits between the white pane and mint frame; never place white text on mint.

Asset production

Generate the mark first. Use the selected result as the reference for later artwork. Build wordmarks and small vector exports from precise shapes and live type. The current approved outputs are documented in the brand assets. The filenames below are working names for future variants.

Primary icon master

live-webview-icon-master.png · 1024 × 1024px · transparent background

Generate a shape exploration, then select and refine one mark. Keep enough clear space for the icon to work in a square crop.

Create one restrained icon concept for Live Webview, a developer tool that refreshes a webview preview after a successful frontend build. Use a compact front-facing rounded window frame with a thick header edge and a dark inset. A smaller warm-white preview pane overlaps its lower-right corner and projects slightly beyond the frame. Preserve this layered layout; do not replace it with two equal windows side by side. Inside each screen, show the same miniature page layout: a heading represented by a long horizontal bar and a shorter text line beneath it. Both screen interiors must have a 3:2 aspect ratio. Use identical proportional placement: 20% left gutter; heading at 18% from the top, 60% wide and 12% high; text line at 38% from the top, 40% wide and 8% high. Scale this exact layout into the front pane. Keep both rear rows visible above the overlap. No letters, glyphs, or abstract symbol inside the screens. This suggests an edit reflected in the preview while retaining the strong window-and-pane silhouette. Mint #78DDB4 frame, charcoal #202623 inset and separator, warm white #F4F5ED front pane. Warm-white content rows in the source; charcoal content rows in the preview. A shallow deep-mint #344E43 rim at most; flat treatment first, no gloss. Transparent outer background, front view, balanced clear space. Clarity and recognition first; personality is only a minor quality of the rounded forms. No text, cursor, code brackets, arrows, browser dots, play/pause symbols, mascot, face, neon, or extra layers. Make an original software-window mark, not a stack of paper documents.

Horizontal wordmark

live-webview-lockup.svg · 1200 × 240 viewBox · transparent background

Typeset this in a vector editor. Use the approved flat mark and Rubik 600; do not ask an image model to generate the lettering.

Create a horizontal Live Webview lockup from the approved flat mark and the exact text "Live Webview" set in Rubik 600. Title case, restrained letter spacing near -0.025em, adjusted optically. Icon at left, wordmark at right. Match their apparent weight and align their optical centers. Start with a gap equal to one quarter of the icon width, then adjust by eye. Keep at least half an icon-width of clear space around the entire lockup. Produce dark-on-light and light-on-dark versions. No slogan inside the logo, no stretched lettering, no shadow on text. Keep editable type in the working file and convert the final distribution SVG's lettering to outlines. Preserve the font license with any bundled font files.

Check the result

  1. At 32px, the overlapping window-and-preview silhouette remains clear, and the same miniature page layout is visible in both screens. If it reads only as stacked documents, refine the content relationship without discarding the preferred layout.
  2. The one-color version works without lighting, texture, or mint. Inspect 16px and 32px exports at actual size.
  3. The wordmark is exactly “Live Webview”. Type remains substantial and readable.
  4. The main impression is a useful developer tool. Any personality comes from the form and stays secondary.
  5. The final files contain no borrowed reference artwork, unintended lettering, or decorative elements added by the generator.

The 256px icon is included in the extension package. Future variants must preserve the approved geometry and follow the packaging allowlist.

References and status

Joel selected the combined direction and clarified that personality is the least important part, acceptable as a small supporting note. Joel wanted the mirrored edit/preview relationship to be clearer, then preferred the original overlapping layout over two side-by-side panes. This study retains that layout. Joel found the stepped symbol arbitrary and its alignment poor, so both screens now use a shared heading-and-text-row layout. Joel approved the refined mark for the GitHub repository and extension package, including its colors, Rubik wordmark, and construction proportions.

  • GitButler: graphic contrast and a simple, strong silhouette.
  • Things: contained forms, rounded corners, and modest object depth.
  • Rubik source and SIL Open Font License: the embedded Latin 600 font is from Google's font service.

Construction diagrams use HTML and CSS. The canonical SVG and PNG exports are now included in the repository; the exported header and icon were visually inspected. Document content, links, color contrast, and structure were checked from source; rendered desktop/mobile layout and animation remain unverified because the browser security policy blocked local-file preview.
